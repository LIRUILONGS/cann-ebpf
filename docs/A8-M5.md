# A8：M5 采集与 A/B 对比脚本

日期：2026-11-26
状态：脚本完成；用两份 V4 run 做了 smoke，真实 V4/Orinfer A/B 仍等 Orinfer 窗口。

## 1. 采集

```bash
# 采集 V4 稳态（拒绝覆盖已有目录，前后 health/service）
PROFILE=vllm-ascend LABEL=v4-baseline DURATION=60s \
  BINARY=./cann-ebpf-linux-arm64-m3 sh scripts/m5_capture.sh

# Orinfer 窗口
PROFILE=orinfer LABEL=orinfer-01 DURATION=60s \
  BINARY=./cann-ebpf-linux-arm64-m3 sh scripts/m5_capture.sh

# 只看计划
PROFILE=orinfer LABEL=dry sh scripts/m5_capture.sh --dry-run
```

输出目录含 `collector.log`、`health-before/after.txt`、`service-before/after.txt`、`exit-code.txt`，
以及标准 `spans.jsonl`/`manifest.json`/`summary.*`。

## 2. 对比

```bash
python3 scripts/m5_compare.py \
  --run-a runs/m5/v4-baseline-... --label-a V4 \
  --run-b runs/m5/orinfer-01-...  --label-b Orinfer \
  --binary ./cann-ebpf-linux-arm64-m3 \
  --out runs/m5/compare.md
```

`m5_compare.py` 对两边各跑一次 `diagnose --json`（只读），生成 Markdown：

- 运行信息：run_id/profile/host/kernel/spans/dropped/window；
- 类别分布与 Top functions（count、p50、p95）；
- host 阻塞：measured、off-CPU/futex 比例与累计；
- 硬件层：HBM free/AICore 峰值；
- device join：匹配率、慢 Sync 匹配率、时钟偏移、fallback；
- 判定与限制说明。

## 3. 验证

- `m5_compare.py --dry-run` 通过；
- 用 `a3-compare-process` 与 `a3-compare-system` 两份 V4 run 生成 `compare.md`（2,819 bytes），
  字段/表格正常；这只证明脚本可用，不是业务 A/B 结论；
- `m5_capture.sh --dry-run` 通过。

## 4. 边界

- 只有相同 workload、并发、max_tokens、duration 时对比才有效；
- 对比不计算吞吐/延迟门禁（用 `scripts/overhead_fixed_load.py`）；
- 没有单 request 延迟和 `execute_model` 函数级耗时；
- 没有真实 `device.jsonl` 时 device 列为 0/unknown，不能据此下设备结论；
- Orinfer 当前未运行，A/B 需要授权窗口。
